# 代码与版本管理规范

## 一、分支策略

主干分支为 main，始终保持可发布状态。开发分支从 main 拉取，命名为 feature/需求编号-简述。修复分支命名为 fix/缺陷编号-简述。

迭代结束后合并回 main 并打标签，标签命名规则为 v主版本号.次版本号.修订号。

## 二、提交规范

提交信息须包含类型前缀与简要描述，类型包括 feat、fix、docs、refactor、test、chore。

单次提交应是一个逻辑完整的改动，禁止将不相关的改动混入同一提交。禁止提交包含明文口令、私钥与内部域名的文件。

## 三、代码评审

所有合入 main 的代码须经过至少一名其他开发者的评审。核心链路与涉及权限、资金的代码须经两名评审人通过。

评审应关注逻辑正确性、异常处理、性能与安全风险，不应仅关注代码风格。

## 四、静态检查

流水线中集成静态代码扫描，扫描发现的高危问题阻断合入。扫描规则由架构组维护，新增规则须在迭代回顾会上说明。
