# 研发流程与需求管理规范

## 一、需求管理

需求来源包括客户反馈、内部业务方提出与技术主动性优化三类。所有需求须录入需求池并标注来源、提出人与期望上线时间。

需求评审每周一次，评审通过的需求进入迭代排期。评审不通过的需求应给出明确原因并退回提出人。

## 二、迭代节奏

采用两周一个迭代。迭代第一周周一召开迭代规划会，确定本迭代范围与验收标准。迭代最后一周周五召开评审会与回顾会。

迭代中途原则上不插入新需求。确需插入的，须由产品负责人与研发负责人共同确认，并移出等量的原有需求。

## 三、开发规范

开发前须完成技术方案设计并通过评审，方案应包含接口定义、数据结构变更、异常处理与兼容性考虑。

单元测试覆盖率要求：核心业务模块不低于百分之七十，其余模块不低于百分之四十。覆盖率不达标的分支不予合入。

## 四、验收与交付

需求开发完成后由产品负责人验收，验收标准应在迭代规划时明确。验收不通过的，退回开发并说明具体问题。

需求上线后应跟踪一个完整业务周期，确认无回归问题后方可关闭。
